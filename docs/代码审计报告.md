- **高**：崩溃 / 核心功能不可用 / 数据丢失 / 可被局域网攻击者或恶意网页实际利用的安全漏洞。

# 一、交互层审计（A）

## 1.1 高严重

### A1｜mobile 端：集数列表为空时上/下滑切集必崩
- **位置**：`app/src/mobile/java/com/fongmi/android/tv/ui/activity/VideoActivity.java:1963-1972`、`app/src/mobile/java/com/fongmi/android/tv/ui/adapter/EpisodeAdapter.java:66-71`
- **问题**：`onFlingUp()` 的判断条件是 `getItemCount() == 1` 才走刷新，集数为 **0**（详情接口失败、纯 URL 推送等场景）时落入 `checkNext()` → `EpisodeAdapter.getNext()`。`getNext()` 中空列表时 `max = -1`，`current` 被钳位到 `-1`，执行 `mItems.get(-1)` 抛 `IndexOutOfBoundsException`（已复核确认）。`onFlingDown → getPrev()` 同理。
- **修复**：判断改为 `getItemCount() <= 1`；同时在 `getNext()/getPrev()` 对空列表返回 null 并在调用处判空，双保险。

### A2｜leanback 端：同一崩溃源藏在默认可见的控制栏按钮上
- **位置**：`app/src/leanback/java/com/fongmi/android/tv/ui/activity/VideoActivity.java:427-428、1187-1197`；`app/src/leanback/res/layout/view_control_vod.xml`（控制栏根节点默认可见）
- **问题**：leanback 的「上一集/下一集」按钮始终可聚焦，`onNext/onPrev` 无空列表防护。自动换源搜索期间集数适配器为空，焦点落在「下一集」按 OK 即触发与 A1 相同的 `mItems.get(-1)` 崩溃（leanback `EpisodeAdapter.java:76-86` 同构代码）。
- **修复**：与 A1 一并修——两个 flavor 的 `EpisodeAdapter.getNext/getPrev` 统一加空列表兜底（一处公共修复可覆盖两端）。

## 1.2 中严重

### A3｜收藏页跨配置点播：零反馈 + 可重复触发
- **位置**：`app/src/leanback/java/com/fongmi/android/tv/ui/activity/KeepActivity.java:57-69`、`app/src/mobile/java/com/fongmi/android/tv/ui/activity/KeepActivity.java:83-95`
- **问题**：`VodConfig.load(config, callback)` 未重写 `start()`，点击其它配置下的收藏后无 loading、按钮不禁用；慢网络下连点会重复发起配置下载。
- **修复**：仿照 `SettingActivity.getCallback()`（SettingActivity.java:202-221）范式，补 `Notify.progress` 并在 success/error 中 dismiss、期间禁用点击。

### A4｜配置中心切换配置完全静默

- **修复**：复用 SettingActivity 的 progress + error toast 范式。

### A5｜leanback 直播页配置加载失败后黑屏无兜底
- **位置**：`app/src/leanback/java/com/fongmi/android/tv/ui/activity/LiveActivity.java:260-280、505-511`

- **修复**：error 分支展示空态提示（复用 view_empty）并提供重新加载入口。

### A6｜leanback 控制栏吞掉 DPAD 上下键，形成焦点死路
- **位置**：`app/src/leanback/java/com/fongmi/android/tv/ui/custom/CustomUpDownView.java:36-44`；使用点 `VideoActivity.java:419-426、449-452`、`LiveActivity.java:195-198`
- **问题**：焦点停在「倍速/字幕/片头/片尾」任一按钮时，上/下键一律被消费（调速/调时间，字幕按钮上下键直接弹 SubtitleSettingDialog），无法垂直离开该行；「字幕」一钮双弹窗易误触。

### A7｜播放控制栏 10+ 图标按钮无 contentDescription（TalkBack 不可用）
- **位置**：`app/src/mobile/res/layout/view_control_vod.xml:18-24、65-95、108-133、147-155、200-204`；`view_control_right/lock/rotate`；语音搜索按钮 `app/src/leanback/res/layout/activity_search.xml:24-32`
- **问题**：全项目 flavor 布局 113 处 ImageView 仅 8 处声明 contentDescription（其中 2 处还是 `@null`），屏幕阅读器读到的是「未加标签」。

### A8｜mobile 亮色主题下搜索页白字对比度严重不足
- **位置**：`app/src/mobile/res/layout/fragment_search.xml:21-29`（输入框 `textColor`/`hint` 均白色、背景 `@null`）；`adapter_search_record.xml:11`、`adapter_search_word.xml:11`、`adapter_search_hot_word.xml:19` 白字 chips；`theme_surface = #FFFDF8` 近白背景

### A9｜约 200 处硬编码中文交互文案绕过 strings.xml
- **位置**：`ui/dialog/GitCloudDialog.java`（2888 行中约 196 行含中文 UI 文案，如 :317「退出」、:536「Token 为空」、:611「暂无仓库」）；`PanNetworkDiagnosticDialog.java:192-194、257-258`；`CodecCapabilityDialog.java:76`；`app/src/mobile/.../LiveProgramDateAdapter.java:78-80`（昨天/今天/明天）；`app/src/leanback/.../ConfigAdapter.java:69`（「[当前] 」）

# 二、功能层审计（B / S / Q）

## 2.1 业务逻辑（B）

### 高严重

#### B1｜一键同步请求缺失服务端 token，将全程被 401 拒绝 —— 核心功能疑似整体不可用
- **位置**：`ui/dialog/OneKeySyncDialog.java:356`、`server/process/Action.java:292`（已复核：两文件 0 处 token 引用）
- **问题**：对话框用 `selected.getIp() + "/action?do=sync&mode=%s&type=backup"` 直接拼 URL；`Action.post`（反向推送）同样不带凭据。而接收端 `ServerAuth.java:84,92` 将 `/action` 列入 `isSensitivePath`，**无条件要求 token**。Web 端 Manage 同步（`Manage.java:613` + `remoteUrl:295-306`）会从目标 URL 提取并追加 token，说明 token 机制是后来加固加入的，App 内对话框链路漏改。
- **复现**：A 机一键同步选 B 机 → 推送 → B 端 401 → 重试两次后报「同步失败」。
- **修复**：OneKeySyncDialog 与 Action.post 构造请求时统一附加对端 token（设备配对时交换），或为 `/action?do=sync` 增加受控豁免并校验设备指纹。**这是全报告优先级最高的单点修复。**

#### B2｜History 主键不含 cid，跨配置共用同一行，「继续观看」被静默接管
- **位置**：`db/Migrations.java:21`（`PRIMARY KEY('key')`）、`bean/History.java:39-41`（已复核 `@PrimaryKey key`）
- **问题**：主键只有 `siteKey@@@vodId`，但所有查询（`History.get(cid)`、`find(cid,key)`、索引 `index_History_cid_createTime`）都按 cid 过滤，暗示「每配置一行」的设计意图。实际同一 key 只有一行：配置 B 播放同站点同剧会 REPLACE 整行，配置 A 的进度、倍速、cid 全部被改写。
- **修复**：主键改 `cid + key` 复合并做迁移；若产品意图就是全局一份，则删除所有 cid 过滤查询——二者必须取一，当前是「设计说 A、实现是 B」的状态。

#### B3｜云/LAN 恢复 cid 映射不完整；`force` + 空 backup 组合可清空配置库
- **位置**：`bean/Backup.java:132-165、174-186`；`server/process/Action.java:364-389`
- **问题**：① `restoreConfig()` 只为备份内存在的 Config 建 cid 映射，映射外的收藏/历史原样保留源 cid 落地，指向目标设备无关配置，界面按 cid 过滤后不可见；② `Action.syncBackup` 对 `Backup.objectFrom(...)` 无空校验（对比 `AppBackup.restore:201` 有防护），JSON 损坏或 body 超限被静默吞（`Nano.java:104-117`）时得到空 Backup，`force=true` 下先删后插 → 接口配置全清；③ 恢复顺序是先还原文件/登录态再 restore DB，DB 抛异常时形成半套数据不可回滚。
- **修复**：syncBackup 入口拒绝空配置备份；cid 无法映射时跳过或按 URL 重解析；文件还原移到 DB 成功之后。

#### B4｜`Backup.restore()` 的 clearAllTables 与插入不在同一事务
- **位置**：`bean/Backup.java:89-100`
- **问题**：先 `clearAllTables()` 再逐表 `insertOrUpdate`，无 `runInTransaction` 包裹。中途失败/被杀 → 配置已清、数据只进一半。`AppDatabase.create` 明确配置了 `setTransactionExecutor`（AppDatabase.java:138）却未使用。
- **修复**：包进 `AppDatabase.get().runInTransaction(...)`；或先写临时表再原子切换。
